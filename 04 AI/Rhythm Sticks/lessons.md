# Rhythm Sticks — lessons

- 2026-11-12: Jimmy's first brief was a spoken ramble. Pull out principles, modes and exclusions into `context.md` first, keep personal details (teacher, place, children) out of every committed file, and ask the open questions in a numbered convo with recommended defaults.
- Mention of a living artist's game: record the *interaction mechanic* only, never the visual style (preferences §4b).
- 2026-11-12: Jimmy answered v0.1 inline as review comments. Record the answers verbatim-in-meaning in a new `convo v0.2.md` (never edit v0.1), then fold them into the schematic. "Beads" turned out to mean a beat looper, not a bar of beads, so ask what a visual should *do* before building it.
- 2026-11-12 (build): a hash-only `page.goto` does not reload, so tests that jump between `#mode` URLs silently stay in the old mode. Listen for `hashchange` in the app, and the test also works.
- Crossing a line with `a*b < 0` misses a sample that lands exactly on the line (a drag stepping onto a string's y). Use `(prev < y) !== (now < y)`.
- A palette key that does not exist (`RS.pal.paper`) fails silently on canvas: the old `fillStyle` is kept. Check every colour key when styling.
- Beads: Chromium's fake microphone beeps on its own and fires real onsets; assert `>= n` hits, not `=== n`.
- Panels that start collapsed need opening in a test before `fill` or `click` (Playwright waits for visibility).
- "Home" in a hidden-gear single-page app can mean the app's own start page (reload, new random mode), not the nursery home; ask when the destination is not obvious.
- 2026-11-12: "Remember the microphone permission" is the browser's choice, not the page's. What the page controls is how often it asks: keep one stream per visit where `permissions.query` is unavailable (Safari), release it where the state is `granted`, never retry after a refusal, and give a visible "try again" button. Test with init scripts that wrap or reject `getUserMedia` and count calls.
- 2026-11-12 (notes round): a note saved on one mode can be about another; the app stamps the mode the page was in, so check whether that mode can even do what the note says (the heat map has no sound) and ask which mode was meant. Sources of tap-to-sound lag to check first: a double-tap wait before acting, analyser window size, first-touch audio start, per-event buffer building, and Bluetooth output.
- 2026-11-13 (0.2.0): lag has two halves, the detection and the answer. Put the detector on the audio thread (an AudioWorklet in a Blob URL, `numberOfOutputs: 0` so it runs as a sink) and keep an analyser fallback with a watchdog on its heartbeat. Act on touch-down, not touch-up, and never wait to see whether a second tap follows when the first can be undone by the second.
- A detector that fires on "energy above a threshold, rising faster than its own slower average" also fires at the start of any slow swell from silence. Add a test on the jump over the last ~12 ms; a made-up clap track and a made-up breath swell through `MediaStreamDestination` is a good test with no hardware.
- A game that makes sounds the microphone can hear will trigger itself. Mask the detector for ~140 ms after noisy sounds, and use sine-only sounds in games that listen (echo, hum, breathing).
- Breath sensing from a phone microphone: only the sound of breath is available, not the breath. Offer an input that always works (a held finger), say what it cannot hear, and keep the wording calm and non-medical.
- Test hooks that fake a microphone (`_attachTest`) saved a lot of time; the browser's own fake device also beeps and fires real onsets, so stop the mic in tests that count taps.
- 2026-11-13 (notes round): dictated notes contain wrong words ("Batman objects", "X axis", "arcade typo"). Quote them as written, say how you read each one, and ask when two readings change the build. When several notes describe the same symptom ("audio stops", "volume disappears", "doesn't work"), group them and look for one cause before fixing each.
- Reading the code for a bug note found a second, unreported bug (a loudness that can fall to zero and never recover). Read the code path for every bug note, not only the reported symptom.
- iPad Safari audio: the engine can be "interrupted", not only "suspended"; wake it on every touch and when the page returns, close it on leaving, and set the audio session to playback so the mute switch doesn't silence it.
