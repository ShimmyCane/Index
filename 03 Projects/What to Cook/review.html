2. Overlaps and simplifications

  1. ✅ Device storage helpers, four copies. app.js (read and write), db.js (session), foods.html (readLocal, writeLocal) and recipes.html (readList, writeList) each wrap localStorage in try/catch. Fix: one shared js/store.js. Low risk.
  2. ✅ Error panel, two copies. app.js and foods.html each have reportError and renderErrors. Fix: one shared js/errors.js.
  3. Database error wording, two copies. (proposed, not changed) foods.html has explainSave for the duplicate-key case, next to db.js's explain. Fix: move the duplicate-key sentence into db.js explain, once.
  4. Id check, two copies. The UUID pattern is in app.js and foods.html. Fix: DB.isUuid in db.js.
  5. Date helpers, two copies. app.js has daysBetween and today; recipes.html has isSoon, which does the same job differently. Fix: one js/dates.js. Medium risk: the pantry's "use soon" rule must stay the same.
  6. Sync blocks, four copies in one file. pushAll repeats one pattern for items, check-ins, transcripts and notes. Fix: one helper that takes the table name and the row shape. This is the biggest simplification in the app, and the easiest to get wrong, so test the pantry flows after it.
  7. ◐ One large file, partly done. The sync code moved to js/sync.js; app.js (about 700 lines) still holds pantry and settings. app.js (836 lines) holds pantry, notes, settings and sync. Fix: split into pantry.js, sync.js and settings.js once items 1 to 6 are done.
  8. Inline style blocks. foods.html and recipes.html each repeat tab wrapping and card rules that also belong in style.css. Fix: move them there.
  9. ✅ Two SQL files define the same table. foods_what_to_cook.sql is fully inside what_to_cook_MVP.sql. Fix: move the older file to a supabase/archive/ folder. This needs your OK, since it was written as a paste file.
  10. Repeated SQL pieces. The policy loop is in the setup and MVP files, and the check query is in five files. Keep: each paste file stays self-contained, so it can be pasted alone. This is a deliberate trade-off, not a fault.
  11. ✅ Recipe cuisines do not match the library. recipes_explore.json uses "American", "Chinese" and "Global", which are not library names. Fix: the recipes point at library entries, and "Global" becomes a region.
  12. Summary page will go stale. foods_summary.html lists line numbers from foods.html. Fix: regenerate it after any change to foods.html, or fold it into this page.
