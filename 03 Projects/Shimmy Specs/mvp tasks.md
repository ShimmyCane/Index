## Phase 2 — Data files (structure only, demo content)

- [ ] **D1. `data/import.schema.json`** — JSON Schema (draft 2020-12) for the project file in `mvp schematic.md` §5.1. Every property optional; `additionalProperties` allowed.
- [ ] **D2. `samples/sketch-project.json`** — the §5.1 example, `kind: "sketch"`, obviously synthetic, no real place names.
- [ ] **D3. `data/drivers.json`** — drivers for: scope (new, addition, alteration, repair, restoration, historic), occupied, use groups (A, B, E, I, M, R-1, R-2, S), construction types (IA, IB, IIA, IIB, IIIA, IIIB, IV, VA, VB), sprinklered yes/no, repair types (masonry, roofing, windows, concrete, waterproofing, sealants, coatings, doors, interiors), contract family (AIA) and delivery (DBB, CMAR, DB). `explain` = one plain sentence each, no code citations beyond chapter numbers.
- [ ] **D4. `data/survey.json`** — question groups: Scope, Use and size, Code, Repair types, Contract. Each question `{ id, ask, type: one|many|text|number, options:[{id,label,sets:[driverIds]}], from: "<import path>" }`. Contract question offers AIA variants as labels only: `A101 + A201`, `A102 + A201`, `A104 (abbreviated)`, `A105 (small project)`, `A141 (design-build)`, `A133/A134 (CM)`, `Other / not sure`. Mark `[?] verify variants with Jimmy` in a `note` field.
- [ ] **D5. `data/keywords.json`** — text-dump rules `{ pattern (regex, case-insensitive), sets: [driverId], label }` for obvious terms: "type ii-?b", "sprinkler(ed)?", "cmu|concrete masonry", "repoint", "re-?roof", "tpo", "occupied", "historic", "landmark". Each hit must show the matched text.
- [ ] **D6. `data/uniformat.json`** — Level 1 and the Level 2/3 elements needed by the PPD for Divisions 01–14 work (A10, A20, B10, B20, B30, C10, C20, C30, D10, E10, E20, F10, F20, G10 …) with titles. Mark the file header note "titles to verify against current UniFormat".
- [ ] **D7. `data/sections/index.json`** — library list `{ number, title, division, template: "<file>" | null }`, seeded from `knowledge/base sections.md` (Divisions 01–14 only). `template` is null except the demo.
- [ ] **D8. `data/rules.json`** — recommendation rules per §5.3, only those already stated in `knowledge/base sections.md` "When" column and the Type IIB example. Each rule's `why` quotes that column.
- [ ] **D9. `data/sections/_demo.json`** — the §5.4 example extended to: 3 parts, 6 articles, ~12 paragraphs, 4 questions (one `one`, one with `sets` cascade, one with a `when` condition, one with an impact on a section not in the book). Title "Demo Section — not a real spec". Labels like "Option A/B/C", explanations "Demo explanation for …". **No real product or standard claims.**
  - Check (all D tasks): `node tools/validate_data.js` (write it in this task) parses every JSON file, checks every driver/section/question id referenced exists, exits non-zero on error.

## Phase 3 — Engine

- [ ] **E1. Conditions.** `js/template.js` `evalWhen(when, ctx)` for `all/any/not` over driver ids and `qid=optionId`. Unit tests in `tools/test_engine.js` (plain Node `assert`).
- [ ] **E2. Drivers from answers.** Collect drivers from survey answers, import file, accepted keyword hits, and option `sets` (repeat until no new drivers; stop after 10 passes and log an error).
- [ ] **E3. Recommender.** `js/recommend.js`: apply `rules.json`; per section keep highest level and all reasons; always include sections named by keynotes (`level: required`, why: "keynote <key>").
- [ ] **E4. Draft builder.** `js/draft.js`: from template + answers → filtered parts/articles/paragraphs → PageFormat numbering (`1.01`, `A.`, `1.`, `a.`) computed after filtering → text with `[[qid]]` replaced. Return both a structured tree (for UI chips) and plain text.
  - Check: test that hiding a paragraph renumbers the rest without gaps.
- [ ] **E5. Decisions.** `js/decisions.js`: `record({...})` per §5.5, auto id, `by` from ⚙️ name (default "unnamed"), timestamps ISO.
- [ ] **E6. Flags.** `js/flags.js`: raise flags per §5.6 from (a) option impacts, (b) impacts on sections not accepted → level `decision`, (c) edit conflicts (E7). De-duplicate by `(section, from, note)`.
- [ ] **E7. Hand edits.** Per §5.7: stable paragraph keys, store edits with a hash of the generated text (simple string hash is fine); on regenerate raise a `review` flag with old/new generated text; never overwrite an edit.
  - Check (E1–E7): `node tools/test_engine.js` passes.

## Phase 4 — Screens

- [ ] **U1. Start.** New sketch project (asks for a name; `kind: "sketch"`), load sample, import JSON, list recent from localStorage, export.
- [ ] **U2. Import.** Text area for the text dump + file drop for the project file. Shows recognized fields, keyword hits as accept/reject chips (each records a decision), and unknown keys under *Extra*.
- [ ] **U3. Survey.** Render `survey.json` groups as stacked +/− panels. Pre-fill from import (`from` path). Under each answer list the drivers it sets.
- [ ] **U4. Sections.** Grouped by division (badge colors). Row: number, title, level badge, *why* (expand), Accept / Reject (asks reason) / Add section (pick from library). Rejected rows stay visible, struck through.
- [ ] **U5. Section workspace.** Questions by Part (tinted gutter) with option cards; draft below with bracket chips (hover = explanation tooltip; click = right panel). Right panel stacked +/− panels: Explanation, Perspectives (master guide / manufacturer / performance / contractor, show "—" if empty), Impacts, Decisions for this section. Click a paragraph to edit inline (contenteditable, plain text); edited paragraphs get a small ✎ mark.
- [ ] **U6. Flags board.** All flags, filter by level/section/status; mark done/dismissed with a note (records a decision). Section workspace shows the same flags in its gutter.
- [ ] **U7. Decisions log.** Table, filter by section/kind/user, export JSON.
- [ ] **U8. Outputs.** Tabs-as-stacked-panels: PPD (accepted sections grouped by their `uniformat` element; sections without one under "Unassigned"), Outline (paragraphs with `outline: true`), Full (whole section text). Toggle "show decision notes". Copy and download `.txt` / `.md`.
