Make 3D V2: how the page fits together

Summary of index.html, with the CSS and JavaScript it depends on (css/app.css, js/ui/app.js, js/viewer/viewer.js). Line numbers are from the current files. Read it after the V2 merge; the layout and most of the wiring are shared with V1 (V1/).

1. The big picture

Arrows show the usual direction of calls. The page reads and writes the engine, draws through the viewer, and saves to the device or the cloud.

Layout values worth knowing (css/app.css)

  • .gear (line 190): 68px button, lower right. Its position is set by right and bottom.
  • .drawer (line 196): Settings and Library width is min(360px, 92vw); max height 70% of the screen. Raise 360px for a wider panel.
  • .libbtn (line 173): the Library button sits to the left of the gear.
  • Narrow screens (line 206): on iPad portrait and phones the side panel sits above the view. The breakpoint is in that block.

7. Notes for the next change

  • Every change to the model goes through applyOp (app.js line 94). Add new behaviour there, not in the event handlers.
  • The viewer reads a model and never changes it; keep that rule when adding features.
  • The page sets two debugging globals for the headless checks: window.__m3dViewer (existing) and window.M3D_viewer (added in V2). They can be merged into one later.
  • The staged passes (js/core/stages.js) exist and are tested, but the viewer still uses the full replay; wiring them in is a later step.
